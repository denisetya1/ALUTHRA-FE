# Anti-slop UI audit 001

Date: 2026-09-20
Mode: AFTER
Scope: `ALUTHRA-FE`

## Design read

Reading this as: an internal game administration portal for ALUTHRA operators, using the owner's clean light and dark direction, blue action color, and Outfit typography, with ENERGY 1 / RHYTHM 1 / MOTION 1.

The design direction comes from the owner's earlier explicit UI guidance. There is no `DESIGN.md`, so the audit treats that guidance as the current source of direction.

## Findings

1. **HIGH - R-02: em dash characters are rendered as empty-value placeholders.** Items, Cards, Relics, Shop, Presents, and Players use `—` in table cells. The hard gate forbids this character in UI text. Replace it with an honest label such as `Not set`, `None`, or a visually hidden accessible label paired with a neutral placeholder.

2. **HIGH - R-03: primary interactive targets are below the required 44px mobile size.** The shared Button sizes are 24px, 32px, 36px, and 40px high, while the sidebar collapse control is 27px. These sizes make row actions, pagination, form actions, and navigation controls too small for reliable touch use.

3. **HIGH - R-24: Events and News are presented as normal navigation destinations although the modules are unavailable.** Both links lead to the generic placeholder route and are not marked `Coming soon` in the sidebar. Remove them until implemented or expose their unavailable state before navigation.

4. **HIGH - R-27: data screens do not implement all required loading, empty, and error states.** There are no route-level `loading.tsx` or `error.tsx` files. Several lists provide an error or empty row, but server navigation has no explicit loading state and the state language is inconsistent across modules.

5. **HIGH - R-32: Reset Player explicitly removes its visible keyboard focus ring.** `reset-player-button.tsx` adds `focus-visible:ring-0` to the trigger. This overrides the shared shadcn focus treatment and makes that destructive action harder to track with keyboard navigation.

6. **HIGH - R-25: the Epic rarity badge misses WCAG AA contrast for normal text.** The light-theme combination `#9a6700` on `#fff4d6` measures approximately 4.44:1 at an 11px text size, below the required 4.5:1.

7. **HIGH - R-35: a clean production verification is not currently reproducible.** Lint and TypeScript pass, but the production build fails when `next/font/google` cannot fetch Outfit. The UI depends on a remote build-time font request, and there is no recorded full click-through for authenticated screens, mobile, and both themes.

8. **MEDIUM - R-04: the icon language is decorative and inconsistent rather than content-led.** The sidebar mixes Unicode symbols, sparkle marks, chess symbols, and a gift emoji, while actions use Lucide. No relevance or identity rationale is documented, and the mixed weights visibly fragment the navigation.

9. **MEDIUM - R-09: the `ADMIN ACCESS` capsule above the login heading repeats context without adding state.** The page title, copy, and footer already identify the administration portal. The bordered sparkle capsule behaves as decoration rather than useful status.

10. **MEDIUM - R-12: elevation is applied as a component default rather than hierarchy.** Every shared Card uses `shadow-sm`, inputs use `shadow-xs`, and dialogs use `shadow-xl`. Because most surfaces are elevated, shadow no longer distinguishes the modal or the active work surface.

11. **LOW - R-06: wide-tracked uppercase eyebrow text is used throughout as a generic administration motif.** Labels such as `WORLD MANAGEMENT`, `MASTER DATA`, and `SYSTEM SETTINGS` repeat the same typographic treatment without a documented ALUTHRA-specific reason.

12. **LOW - R-20 and R-31: the authenticated workspace lacks a documented identity motif and decision rationale.** The login screen carries a realm sigil motif, but the admin pages reduce to a standard sidebar, heading, filter, table, and card shell. Color, layout, spacing, cards, and icon decisions are not recorded, so the workspace could be rebranded with little structural change.

13. **LOW - R-27: empty-state guidance is uneven and often omits the next action.** Some tables say only `No presents yet`, while Cards explains why it is empty. Empty states should consistently distinguish first use from filtered-to-zero and point to the relevant Add or Reset action.

## Evidence and checks

- Runtime login page inspected in light and dark themes at `http://localhost:3001/login`.
- Light and dark theme toggles worked on the inspected login screen.
- Keyboard semantics and source behavior were inspected for shared buttons, dialogs, sidebar controls, filters, and forms.
- `npm run lint` completed with no errors and one existing `next/image` warning.
- `npx tsc --noEmit` completed successfully.
- Production build verification is blocked by the remote Outfit font fetch and is recorded as finding 7.

## Positive observations

- The active navigation state represents a real current-page state.
- Form submissions now provide success and error feedback through toast notifications.
- The Reset Player dialog uses a real modal, supports Escape through Radix, and requires typed confirmation.
- The palette is restrained and the light and dark login themes are visually coherent.
